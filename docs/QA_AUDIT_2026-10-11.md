## Critical / high-priority findings (not fixed)
1. **P0 multi-tenant privacy:** /api/icloud/events authorizes *any* valid Supabase user token to access the pilot family's shared Apple credentials and calendar. Must restrict to authorized pilot admin immediately, then implement tenant-scoped credentials before onboarding other families.
2. **P1 iCloud recurrence:** ICS parser does not expand RRULE/RDATE/EXDATE/RECURRENCE-ID; timezone and all-day semantics are incomplete. Events may be missing or displayed at wrong time.
3. **P1 duplicate suppression:** iCloud events are deduplicated by title/start/end/location across calendars, risking loss of distinct legitimate events.
4. **P1 training camp atomicity:** multiple client-side inserts and participant links are not transactional; rollback can fail and leave orphan/partial data. Replace with a database transaction/RPC and RLS.
5. **P1 auth on iPhone:** callback cookie handling and session persistence not yet verified in real Safari. Test magic-link flow, reload, expiry, cross-app opening and errors.
6. **P1 multi-tenant design:** persons/calendar_events/event_persons access controls and family scoping must be audited in Supabase; UI currently relies on pilot-specific name matching.
7. **P2 provider status:** connection catalog is a UX prototype; it does not establish customer-specific OAuth or third-party connections.
8. **P2 ICS import:** timezone-qualified timestamps and recurrence unsupported; import needs reliable identity and conflict handling.

- Integrations: invalid credentials, revoked access, 429 rate limit, provider timeout, duplicate sync, re-connect.
- Data safety: ensure no credentials in browser, logs or repository; verify backups and migration rollback.
